# 手写板画板 UI 方案对比

日期：2026-11-26
状态：分析记录；最终方向见 `openspec/changes/bootstrap-tablet-sketch/specs/pen-first-ui/spec.md`。

## 1. 现状

现有 `MacAppControlDeck` 的 UI 草图是鼠标优先的 Excalidraw Web 画板：

- 顶部 Excalidraw 工具栏、右侧属性面板、小图标、小下拉
- 多画布、素材库、PNG/JSON 导出
- 鼠标绘制，未接压感/倾斜
- 窗口关闭释放 WebView，默认非常驻

手写板适配不能只换皮肤，要同时解决：

1. **视觉尺寸**：按钮、滑杆、菜单对笔尖太小
2. **交互路径**：笔不想每次回到工具栏
3. **输入语义**：压感、倾斜、橡皮、侧键、板载键

## 2. 方案 A：鼠标兼容增强版

保留当前布局，只放大和增强：

- 工具栏按钮 44–48pt
- 工具 6–8 个，其余收进「更多」
- 属性面板改大号滑块/分段按钮
- 画布固定比例，平板映射到画布
- 接压感、倾斜、橡皮
- 笔侧键 1 橡皮、侧键 2 撤销/平移
- 8 键映射常用动作

**优点**：改动小，鼠标/手写板都能用，风险最低。  
**缺点**：仍是鼠标式布局，画布被工具栏占用，沉浸感一般。

## 3. 方案 B：画布沉浸模式

画布优先，隐藏 chrome：

- 顶部 32pt 细条，落笔自动隐藏
- 左侧 56pt 工具轨，右侧可折叠属性抽屉
- 笔侧键呼出径向菜单
- 8 键做硬件快捷键
- 画布锁定：笔只在画布内，画布外笔迹丢弃
- 左手模式镜像
- 画布周围深色留白，明确可画区域

**优点**：最像绘图板，画布利用率高。  
**缺点**：需改布局、加径向菜单、做画布锁定与输入仲裁；用户要记快捷键。

## 4. 方案 C：双模式切换（推荐）

设置中提供输入模式：

| 模式 | 布局 | 笔的行为 | 适合 |
|---|---|---|---|
| 鼠标模式 | 当前布局 | 笔就是鼠标，可点工具栏 | 日常、鼠标用户 |
| 手写板舒适模式 | 放大工具栏 + 属性面板 | 映射整个窗口，笔可点工具，笔迹只落画布 | 第一次用手写板 |
| 手写板沉浸模式 | 画布优先 + 隐藏 chrome + 径向菜单 | 画布锁定，工具走侧键/板载键 | 长时间画图 |

推荐默认「手写板舒适模式」，再让用户切「沉浸模式」，避免一上来逼用户记 8 个键。

## 5. 画布映射策略

| 策略 | 笔能到哪 | 笔迹范围 | 工具操作 | 难度 |
|---|---|---|---|---|
| 全窗口映射 | 整个窗口 | 仅画布矩形 | 笔可点工具栏 | 低 |
| 画布锁定 | 仅画布矩形 | 仅画布矩形 | 径向菜单/板载键 | 中 |

建议 P0 先做全窗口映射；画布锁定放 P1。

## 6. 与鼠标指针的冲突

macOS 只有一个系统光标，数位板和鼠标共同写同一个光标，最后事件覆盖前一个。

冲突点：

- 同时移动抢光标
- 从鼠标切到笔光标瞬移
- 笔越界点击穿透
- 鼠标想离开画布被锁死
- 窗口不在前台点到背后 App
- 官方驱动与自研驱动同时跑出现双光标

解决：

- 输入源仲裁：笔在感应区/落笔优先，鼠标移动立即让位
- 笔进入画布先锚定到上次位置/中心再绝对映射
- 绘图越界丢弃
- 只转换笔事件，鼠标原样放行
- 只在目标窗口前台启用画布锁
- 只保留一个事件源
- Sketch 内置虚拟笔光标，鼠标完全不受影响

## 7. 推荐实施顺序

- **P0**：放大工具栏/属性面板、压感/倾斜、橡皮、固定比例画布、笔侧键映射
- **P1**：手写板舒适模式、落笔隐藏 chrome、左手镜像、8 键默认映射
- **P2**：画布锁定、径向菜单、沉浸模式、压感曲线预设

## 8. 风险

- Excalidraw 是 React/Web 布局，深度改 UI 成本高；优先 CSS + 外层覆盖层，不动内核。
- Excalidraw 原生 freehand 对压感支持需验证；不接受就接自定义 brush。
- 笔点小按钮易误触，所有可点区域加 hit slop。
- 掌压/侧键误触靠「笔尖在感应区 + 按下才生效」与边沿检测。
- 画布锁定后窗口失焦，笔点可能落到背后 App；只在 Sketch 前台启用锁定。
