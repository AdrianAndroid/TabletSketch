# 采集器独占失败自愈

## 问题

采集器以 `--grab` 启动时，如果 `IOHIDManagerOpen(seize)` 失败（覆盖安装的竞态、残留进程占用设备等），当前实现会退回只读模式并**永久放弃独占**：

```
{"state":"grab-failed","message":"独占失败，退回只读"}
```

只读模式下 digitizer 的悬停与坐标仍能收到，笔看起来正常；但板载键走的 keyboard report 收不到，**8 个键全部失效，屏幕卡片不亮、动作不执行**。用户实测复现过这条路径，表现为“以前好过、后来突然全废”，且只能靠杀进程重启碰运气。

## 目标

- `seize` 失败后退避重试：1.5s 起、每次翻倍、8s 封顶，持续重试直到抢到设备。
- 抢到后自动恢复独占：重新枚举设备、重新锁定鼠标 / Digitizer / 键盘接口，笔与板载键立即恢复，无需重启应用。
- 重试期间不打断书写：不向界面发 `disconnected`，避免连接状态闪烁；只读模式下的笔事件保持可用。
- 状态可见：重试中 / 已恢复两类状态透传到设置面板的 HID 状态字段。

## 非目标

- 不改采集器的独占策略（仍是“应用运行即全接口 seize”）。
- 不改按键编码映射、笔状态机、坐标与压力链路。
- 不做常驻后台拦截（用户已确认“不点开就不用”）。

## 影响

- `Sources/TabletSketchHID/HIDReader.swift`：退避重试、close/reopen、重新枚举、重建接口锁。
- `Web/app/hid-bridge.js`：把 `retry` / `recovered` 转成可读状态文案。
- `Tools/ui-test/*`：状态文案与重试状态机的最小回归。
