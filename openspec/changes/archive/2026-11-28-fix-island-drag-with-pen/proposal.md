# 变更：修复手写笔直接拖动浮岛把手

## Why

用户真机反馈：浮岛顶部的拖动把手本应「按住就拖」，但当前只有在「选」工具下才顺手；用画笔/橡皮等工具时，笔按在把手上移动，浮岛不跟手，整体仍有卡顿感。

根因在 `Web/sketch/src/tablet-sketch.js` 的 UI 命中分支：笔报告只转发 `began` / `ended`，**`changed` 被直接丢弃**。因此笔在把手或浮岛内部移动时，`onGripDown` 注册的 `pointermove` 收不到事件，浮岛不动；只有笔移出浮岛落到画布后，`changed` 才作为画布指针事件转发，拖动才「突然生效」。这也让绘制工具下的拖动混入画布指针事件，产生额外开销与工具依赖。

## What Changes

- 笔落在 `[data-ts-ui]` 上时，`changed` 阶段也合成 `pointermove` 派发到命中元素，让把手的拖动处理器收到连续移动。
- 浮岛拖动用 `requestAnimationFrame` 合并移动更新，松手时直接写 `left/top` 再交给 React，避免回弹一帧的视觉卡顿。
- 拖动期间暂停压感读数板的按帧更新，避免无关 React 渲染抢占主线程。
- 保留原生鼠标路径不变；笔与鼠标都遵循「把手即拖动入口」，不依赖当前工具。

## Impact

- 手写笔可在任意工具下直接拖动浮岛，把手内的小幅移动也跟手。
- 拖动浮点不再受当前工具影响，也不再向画布派发多余指针事件。
- 离屏回归新增笔在把手内移动的用例；原有鼠标拖动、吸附、复位行为不变。
