# 布局设置页顶部真实 UI 预览，可直接拖动重排

## 问题

设置面板的五处布局页（左浮动岛 / 右浮动岛 / 笔键 1 / 笔键 2 / 板载键）顶部只有一张纯文字的「形态预览」，列出「内圈 / 更多 / 外圈 / 浮岛 N 格」的文字标签，与真机实际看到的按钮外观差距很大。用户必须回到主界面才能确认某个顺序在真实 UI 上长什么样。

用户反馈：**希望设置里面所有可以设置的地方，在顶部都增加和 UI 界面一样的界面，并且可以在这个预览界面上直接拖动重排**。上一轮已实现「列表拖动中实时预览、松手落坑保存」，本变更在此基础上把预览从文字描述升级为高度仿真的 UI，并让预览本身成为可拖动重排的操作面。

## 目标

- 左浮动岛 / 右浮动岛 / 笔键 1 / 笔键 2 四页顶部各渲染一张与真实 UI 高度仿真的预览：
  - 左岛：竖排的样式按钮条（图标 + 当前值文本）。
  - 右岛：与真机一致的图标网格，列数同样按「总数 > 10 才双列」自动切换，尾部带「更多」。
  - 笔键 1 / 笔键 2：与真实径向菜单一致的 SVG 扇区环，内圈 +「更多」+ 外圈，图标 / 色块与当前态一致。
- 预览中的每个槽位都可以直接拖动重排，与下方「当前按钮」列表共用同一份 `displayIds` 预览态，两处同步更新。
- 沿用上一轮的保存时机：**拖动中只更新本地预览态，松手落到坑位才写入 `layout.v2` 并广播**；取消拖动 / 拖到面板外则回退。
- 预览复用 `Icons` 与既有 CSS 观感，但使用独立的预览专用组件与类名，不挂载真实输入组件、不订阅笔位置、不触发任何真实动作。

## 非目标

- **板载键（键位页）保持现状**：仍是 8 行下拉选功能，不在本变更内增加 UI 预览（用户已明确）。
- 不改变 `layout.v2` 的数据结构、校验、默认值、配置档机制。
- 不引入第三方拖拽库，沿用 HTML5 drag 事件。
- 不改浮岛拖动、样式环交互、画布与手写板坐标映射、真机输入分层（R11）。

## 用户已确认的决策

| 决策点 | 选择 |
|---|---|
| 预览形态 | 替换旧文字预览，改为与真实 UI 高度仿真的图形预览 |
| 覆盖页面 | 只覆盖左岛 / 右岛 / 笔键 1 / 笔键 2 四页；板载键保持现状 |
| 保存时机 | 松手落坑才写入配置，拖动中与列表同步、取消回退 |
| 实现边界 | 新建预览专用组件，复用图标与观感，不复用真实输入组件 |

## 影响

- `Web/sketch/src/tablet/settings/SettingsWindow.jsx`：用新预览组件替换 `Preview`，把列表的拖拽回调接到预览槽位上。
- 新增 `Web/sketch/src/tablet/settings/LayoutPreview.jsx`：四种几何的高度仿真预览组件。
- `Web/sketch/src/tablet/chrome.css`：预览容器、环扇区、拖动源 / 落坑态样式。
- `Tools/ui-test/main.js`：追加预览渲染与预览上拖动落坑保存的离屏回归。
- 规格：`app-settings` 修订预览场景，`pen-first-ui` 补充「设置内预览不接管输入」的边界。
