# 设计：TabletSketch 首个可运行版本

## 1. 目标与边界

本设计只覆盖 `bootstrap-tablet-sketch` 的首个可运行版本（P0）：

- 独立 macOS App，不依赖 `MacAppControlDeck`。
- 只读 HID，读取 Deco 640 的完整笔数据。
- 压感/倾斜/橡皮进入 Excalidraw 画布。
- 16:9 等比例画布，笔迹限制在画布内。
- 笔侧键 + 8 个板载键的基础映射。
- 鼠标模式保留，无设备自动回退。
- 不做系统级指针接管，不做 KEXT/DriverKit。

## 2. 总体架构

```text
┌──────────────────────────────────────────────────────────────┐
│                   TabletSketch.app (Electron)                 │
│                                                              │
│  主进程 (Node)                                                │
│  ├─ 窗口 / 菜单栏 / 文件存储 / 导出                           │
│  └─ spawn tablet-sketch-hid ──▶ Swift 小工具                  │
│                                    └─ IOHIDManager 只读       │
│                                       Deco 640                │
│                                       stdout: 逐行 JSON       │
│                                                 │             │
│                                          IPC（contextBridge）│
│                                                 │             │
│  渲染进程 (React)                                ▼             │
│  ├─ 自绘 chrome：顶部条 / 右侧浮岛 / 径向菜单 / 样式气泡      │
│  ├─ Excalidraw 0.18.1（fork，原生 UI 已拆掉）                 │
│  └─ pushPenSample()：笔采样直连绘制链路，不经 DOM 事件        │
│                                                              │
│  文档：~/Pictures/TabletSketch/Sketches · 草稿 · 导出          │
└──────────────────────────────────────────────────────────────┘
```

分层原则：

1. **HID 工具只负责读字节**，不碰 UI、不碰画布，输出标准化采样行。
2. **PenInput 只负责状态机和标准化事件**，不直接生成笔迹。
3. **CanvasMapper 只负责坐标变换**，不判断工具。
4. **渲染进程的 chrome 只负责布局和控件**，不直接读 HID。
5. **Excalidraw 只负责画布与图形模型**，不承担任何 chrome。
6. **文档层只负责文件**，不持有渲染状态。

换输入设备只改 HID 工具，换 UI 只改 chrome 层，互不牵连。

### 2.1 架构决策：Electron + fork Excalidraw

首个可运行版本采用 **Electron + fork Excalidraw 源码**，替代最初的"WKWebView + AppKit 自绘外壳"。

**为什么换。** 原方案要让网页"看起来不像网页"，需要三个东西同时成立：CSS 隐藏清单一个不漏、一层全窗口透明视图拦截所有输入、右键菜单和文字编辑器单独改造。其中输入拦截层是最容易出 bug 的部分（事件按位置命中，但滚动和捏合要再转发回 WebView）。更根本的问题是，这套设计的每一步都在"减少破绽"，而不是"消除破绽"——每跟进一个 Excalidraw 小版本，就要重新排查一遍。

换掉之后，"原生 vs 网页"这个矛盾本身消失了：整个 App 就是一个定制到很深程度的 Excalidraw，视觉统一是免费的。

**为什么 fork 源码而不只是覆盖。** 官方 props 能接管一部分 UI，但有三处接管不了：属性面板没有关闭开关（只能 CSS 藏，`docked` 状态还在）、右键菜单结构固定、工具栏与浮岛的位置和交互冲突。而决定手感的那个改动——把 HID 采样直接喂进绘制链路——必须改 `App.tsx` 的指针处理，覆盖式做法只能合成 DOM 事件，多一跳、字段还得靠猜。

**被否决的方案。**

- *WKWebView + AppKit 自绘外壳*：视觉一致性靠模仿，事件仲裁层复杂，随上游版本漂移。留作备选，如果 Electron 的输入延迟实测不可接受再回退。
- *只覆盖不 fork（npm 依赖 + patch-package）*：改动点会从 2 个涨到十几个文件，patch 每次升级都要重打，反而更脆。
- *重写画布（自绘矢量引擎）*：图形模型、命中测试、绑定关系、文本排版、撤销栈、SVG/PNG 导出、素材库全部重做，工作量与收益不成比例。

**接受的代价。**

| 代价 | 说明 |
|---|---|
| 包体积 | 150–200 MB，原来只有 5 MB 资源 |
| 冷启动 | 1–2 s，靠"窗口先出现、内容后填充"掩盖 |
| 跟随上游 | 钉死 0.18.1，只 cherry-pick 安全修复 |
| 系统集成 | 窗口材质、菜单栏等是模拟的，不如 AppKit 原生 |

**fork 的纪律。** 三条硬规矩，缺一条这个 fork 半年后就会烂：

1. 源码走 git submodule（`Web/vendor/excalidraw`），钉在 `v0.18.1`（commit `a2ec288`）。改动提交在 submodule 里，主仓库只记指针；同时用 `git format-patch` 导出到 `Docs/patches/` 做兜底。后期切到自己的 fork 仓库，只换 submodule 地址。
2. 每处改动都打 `// TS-FORK:` 注释，说明为什么改。任何时候 `grep -rn "TS-FORK"` 就能列出全部改动点。
3. 官方 props 能解决的绝不改源码，改源码是最后手段。`Docs/fork-changes.md` 维护给人看的改动清单。

## 3. HID 输入层

### 3.1 设备与通道

| 通道 | UsagePage / Usage | Report ID | 用途 | 本项目用法 |
|---|---|---|---|---|
| A | `1 / 2` Mouse | `9` | 系统鼠标、绝对 X/Y、压感 | 只作观察，不作为主输入 |
| B | `13 / 2` Digitizer | `7` | 标准笔/橡皮/InRange/压感/倾斜 | fallback / 对照 |
| C | `0xFF0A / 1` Vendor | `2` | 完整笔数据 + 8 板载键 | **主输入** |

首版以 C 通道为准。原因：完整笔数据、板载键和厂商扩展都在 C；A/B 由系统接管，数据不完整。

### 3.2 初始化

```text
Output Report (20 bytes):
02 B0 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

- 只在打开手写板模式/窗口时发送一次。
- 发送后等待 ACK；ACK 必须过滤：`0xB4 / 0xF2 / 0xF8`。
- `0xC0` 是 OutOfRange（笔离开感应区），不是 ACK：收到即结束当前笔迹并重置笔状态，否则笔状态永不归零、笔迹不断开。
- 未过滤 ACK 可能被当成坐标 `(0,0)` 的笔报告，导致光标跳左上角。
- 初始化失败时不要重试到卡死；提示用户并回退鼠标模式。

### 3.3 12 字节笔报告

| 字节 | 含义 | 处理 |
|---|---|---|
| `[0]` | `0x02` | 报告类型校验 |
| `[1]` | 状态位 | bit1/2 笔侧键、bit3 橡皮、bit4 Aux |
| `[2..3]` | X 低 16 | 小端 |
| `[4..5]` | Y 低 16 | 小端 |
| `[6..7]` | 压感 uint16 | `0..16383` |
| `[8]` | TiltX | signed byte |
| `[9]` | TiltY | signed byte |
| `[10]` | X 高 8 | 与 `[2..3]` 拼成 24 位 |
| `[11]` | Y 高 8 | 与 `[4..5]` 拼成 24 位 |

- MaxX `31998` / MaxY `17998`；坐标先归一化到 `0..1`。
- 未知长度/未知 Report ID 直接忽略。
- 所有解析函数必须是纯函数，便于用固定字节数组做单测。

### 3.4 Aux 报告与板载键

- Aux 报告 `[2]` 是 8 键位图；`[3]/[4]` 扩展；`[7]` 是协议预留滚轮方向。
- Deco 640 没有独立滚轮；`[7]` 是否有值待实测。
- 板载键按下/抬起要做去抖（建议 10–20 ms），避免一次按下触发多次。
- 按键映射只在 TabletSketch 前台生效，不注册全局热键。

### 3.5 三态识别

```text
IDLE
  │ 笔进入感应区
  ▼
HOVER          InRange=1, Tip=0, Pressure=0
  │ Tip 闭合
  ▼
CONTACT        Tip=1, Pressure≈0 或很小
  │ 压力超过死区，或开始移动
  ▼
DRAWING        Tip=1, Pressure>阈值
  │ 压力回落到释放阈值
  ▼
CONTACT
  │ Tip 抬起
  ▼
HOVER
  │ 离开感应区
  ▼
IDLE
```

规则：

- **悬停不落笔**，只画笔刷光标。
- **Tip 闭合即起笔**，不要等压力超过阈值，否则轻画会丢、起笔会延迟。
- 压力为 0 时线宽取下限；压力越大越粗。
- 起笔阈值与释放阈值分离（滞回），避免压力抖动导致笔迹断断续续。
- 点击 vs 笔画：Tip 闭合到抬起时间短、位移小于 3–5pt，视为点击；否则为笔画。

### 3.6 压感映射

```text
raw ∈ [0, 16383]
p = raw / 16383
p' = pow(p, gamma)          // gamma 默认 1.0，可在 0.6–1.4 调
width = wMin + (wMax - wMin) * p'
```

- `wMin` 不能为 0，否则轻画不可见；建议 1–2pt。
- `wMax` 由当前工具决定；橡皮用压力控制擦除半径。
- 压力映射按工具保存预设；首版至少支持「钢笔/马克笔/橡皮」三套。
- 倾斜：`atan2(tiltY, tiltX)` 得到笔锋方向；首版可选启用，不启用时不得阻塞笔迹。

### 3.7 输入仲裁

- 同一时刻只有一个源写画布。
- 笔在感应区或 Tip=1：手写板源优先。
- 鼠标移动：鼠标源立即接管，笔暂停写画布。
- 手写板用应用内虚拟笔光标；系统鼠标箭头保持独立。
- 笔在画布内时隐藏系统箭头；鼠标移动后恢复。
- 只转换 TabletSketch 窗口内的笔事件；窗口失焦时停止画布锁定。
- 官方驱动与自研输入不得同时运行；检测到冲突时提示用户只保留一个源。

## 4. 画布映射

### 4.1 默认比例

- 画布默认 16:9，与 Deco 640 有效区一致。
- 整块板映射到画布矩形，等比缩放，不留横向/纵向拉伸。
- 画布周围用深色留白 + 细边框，明确可画区域。

### 4.2 坐标变换

```text
u = (x - minX) / (maxX - minX)
v = (y - minY) / (maxY - minY)

px = canvas.x + u * canvas.width
py = canvas.y + v * canvas.height
```

- `u/v` 超出 `[0,1]`：画布锁定模式下直接丢弃；全窗口模式下允许指针在 UI 上，但不产生笔迹。
- 不允许 `px` 和 `py` 各自拉满不同比例；必须保持 `canvas.width / canvas.height = 16/9`。

### 4.3 4:3 / 1:1 画布

按目标比例 `R` 取最大居中子矩形：

```text
if tabletAspect > R:
    cropW = tabletH * R
    cropH = tabletH
else:
    cropW = tabletW
    cropH = tabletW / R
```

- 只映射裁切后的子矩形，剩余区域不响应笔迹。
- 越界事件丢弃，不夹边；夹边会让画布边缘出现拖尾。
- 画布 UI 上显示裁切边界，用户能看到有效区。

### 4.4 两种模式

| 模式 | 笔能到哪 | 笔迹范围 | 工具操作 | 适用 |
|---|---|---|---|---|
| 全窗口映射 | 整个窗口 | 仅画布矩形 | 笔可点工具栏 | 默认，最实用 |
| 画布锁定 | 仅画布矩形 | 仅画布矩形 | 浮岛/板载键 | 沉浸绘图 |

- 全窗口映射必须做「笔迹裁剪」：坐标落在 UI 上时不画。
- 画布锁定只在 TabletSketch 前台启用；窗口失焦自动解除，避免点到背后 App。
- 画布锁定要有明显视觉提示（边框颜色/锁定图标）。

## 5. UI 设计

### 5.1 布局

窗口即板面：无标题栏，比例锁 160:90（≈1.778:1），除顶部条与浮岛外全部是画布。

```text
┌───────────────────────────────────────────────────────────────────────┐
│  ≡   画布 3 · 已保存                                              ⋯   │ 24pt
├───────────────────────────────────────────────────────────────────────┤
│                                                    ╭───────────────╮  │
│                                                    │       ≡       │  │ 把手（横跨）
│                                                    ├───────┬───────┤  │
│                                                    │ 菜单  │  圆   │  │ 1 / 9
│                                                    │ 画布  │  箭   │  │ 2 / 10
│                                                    │ 素材  │  字   │  │ 3 / 11
│          ●────────┐                                │  笔   │  菱   │  │ 4 / 12
│                   │                                │  擦   │  线   │  │ 5 / 13
│                   └───────▶                        │  手   │  图   │  │ 6 / 14
│                                                    │  选   │  锁   │  │ 7 / 15
│                                                    │  矩   │   ⋯   │  │ 8
│                                                    ╰───────┴───────╯  │
└───────────────────────────────────────────────────────────────────────┘
```

- 顶部 24pt：窗口拖动区 + 画布名（点击打开画布列表）+ 保存状态 + `⋯`（设置/导出/新建/模式）。
- 右侧浮岛：把手 + 可配内容格 + 末尾 `⋯`；最多双排；格数 0–18 可配。
- 双排时先填左列自上而下、再填右列；用户可拖动换位，换位即换键位。
- 浮岛可拖到窗口内任意位置，默认右侧垂直居中；松手 24pt 内吸附边缘。
- 板载键 1–8 绑定「前 8 格」，第 9 格及之后只可用笔点。
- 笔尖样式气泡由侧键唤出，不常驻，替代原「右侧属性抽屉」。
- 落笔时浮岛与顶部条降到 ≤20% 不透明度并禁用指针事件，抬笔 400ms 后恢复。
- 不再有左侧工具轨、底部固定工具条、汉堡菜单、缩放条。
- 左手使用不设单独开关：把浮岛拖到左边即可，气泡自动反向展开。

尺寸依据：窗口按视觉 1:1 约 780×440pt。单排 40pt 时上限 10 格；双排 40pt 时上限 18 格（把手 40 + 9 行 × 40 + 留白 ≈ 424pt）；双排 44pt 时上限 16 格。格数变化只改浮岛高度，不改窗口。

### 5.2 可点区域

- 主格 44×44pt 首选；窗口高度受限时允许 40×40pt，不得更小。
- 滑杆轨道高度不小于 6pt，滑块不小于 28pt。
- 下拉菜单改为大号分段按钮或弹出面板；避免 1px 细线和微小箭头。
- 所有可点区域加 hit slop；笔尖点按允许 2–4pt 误差。
- 二级面板最多两级，内部可滚动，不建第三级。

### 5.3 径向菜单与样式气泡

侧键 1 在**笔光标位置**弹出径向菜单；侧键 2 直达样式气泡（不进菜单）。径向菜单里的「样式」槽是样式气泡的第二入口。三者的边界：**径向菜单管操作**（副本/删除/层级/对齐/分组/锁定），**样式气泡管样式**（颜色/线宽/填充/线型/边角/字号/对齐），**「更多」槽把原生右键菜单原样引出来**（剪切/粘贴/复制样式/层级/链接）。

默认 4 槽、上限 8 槽、设置里可改。外径 `D = 180 + 15 × n`，4 槽 240pt、8 槽 300pt；中心 90pt 圆恒为关闭，扇区只占 `[45pt, D/2]` 环带。4 槽每槽 90°，8 槽每槽 45°，弧长都够笔点。

```
                 笔光标 = 圆心
        ╭───────────────────────────────────╮
        │            ╱╲        ╱╲           │
        │         ╱ 样式 ╲   ╱ 副本 ╲        │   4 槽 · 直径 240
        │        │        │ │        │       │
        │   ╱────┤   ╭──╮  ├────╲           │   中心圆 = 取消
        │  │ 更多 │  │⊘ │  │ 删除 │          │
        │   ╲────┤   ╰──╯  ├────╱           │
        │        │        │ │        │       │
        │         ╲      ╱   ╲      ╱        │
        │            ╲╱        ╲╱           │
        ╰───────────────────────────────────╯

        8 槽 · 直径 300：补入 层级 / 对齐 / 分组 / 锁定
```

交互分三步，每步都只用一个动作：

| 步骤 | 用户的动作 | 系统行为 |
|---|---|---|
| 开 | 按侧键 1 | 以笔光标为圆心弹出，不改选中、不动视口 |
| 瞄 | 笔悬浮移动（不接触板面） | 光标所在扇区实时高亮 |
| 定 | 笔尖接触板面 | 执行该扇区，菜单关闭 |

**独占输入态**是这个设计的关键约束。菜单打开期间笔尖 down/move/up 全部由原生层消费，一个 pointer 事件都不往 Web 发——否则「点菜单」会同时变成「画一笔」。命中测试走极坐标：先算半径分环带/中心圆，再由极角定扇区，边界带 ±2° 吸附防抖。这不违反 §3.7：此时没有任何输入源在写画布。

**「样式」是二级入口**，不是动作。点中后菜单从外向内收缩成 90pt 残圆停靠在光标侧方，旁边展开样式气泡；点残圆、气泡外空白或再按侧键 1 一起关闭。这样「选中图元 → 侧键 → 样式 → 调色」是四个动作，比走原生右键菜单（上游菜单里根本没有颜色项）少且不断链。

**两套上下文**：有选中时 4 槽是 样式/副本/删除/更多（增至 8 槽补 层级/对齐/分组/锁定）；空白时 4 槽换成 粘贴/全选/清空/更多（补 撤销/缩放复位/插入图片/背景切换）。空白上下文下不出现「样式」槽。

样式气泡按上下文换内容、尺寸恒定 320×140、3 行档位按钮：

```
        ● 笔尖
   ╭─────────────────────────────────╮
   │ 颜色  ● ● ● ● ● ●              │   ← 笔 / 橡皮
   │ 线宽  细  中  粗  特粗          │
   │ 透明  100  75  50  25           │
   ╰─────────────────────────────────╯

   ╭─────────────────────────────────╮
   │ 描边  ● ● ● ● ● ●              │   ← 矩形 / 椭圆 / 菱形
   │ 填充  ⊘ ● ● ● ● ● ●            │
   │ 线宽  细  中  粗  特粗          │
   ╰─────────────────────────────────╯
```

为什么不用滑杆：笔点滑杆要命中 28pt 的滑块，误差大；档位按钮可以整块点中。为什么不做翻页：笔操作翻页手感差，且第二页的内容在一屏 3 行里本来就能按上下文放得下。

### 5.4 模式

| 模式 | 行为 | 默认 |
|---|---|---|
| 鼠标模式 | 现有鼠标布局，笔就是鼠标 | 是（默认） |
| 手写板模式 | 窗口即板面、右侧浮岛、笔尖气泡、笔迹裁剪 | 用户显式开启 |

- 只在用户显式开启时发送 init 切 vendor；关闭窗口/退出时释放句柄，若不能回 HID 则提示一次「需拔插恢复」。
- 模式切换必须在菜单/窗口内可见，不要求记快捷键。
- 模式状态本机保存；换机器不跟随账号同步。
- 检测不到设备时自动回退鼠标模式，并提示一次。

### 5.5 浮岛、下拉与溢出

- 把手横跨整行，独立命中区，双击复位；按在工具格上只选工具，不触发位移。
- 拖动期间暂停画布输入（与 §3.7 输入仲裁一致），避免边拖边画。
- 吸附：距边 24pt 内吸附；落在手写区中心则自动吸到最近边，防止长期挡笔。
- 位置与格数写入 `settings.json`；格数变化只改浮岛高度。
- 浮岛里的内容格可以放三类东西：工具、组、「展开型格子」（菜单 / 画布 / 素材）。
- 板载键 1–8 绑定前 8 格，拖动换位即换键位；第 9 格起只可用笔点。

**自动溢出**：`⋯` 里的工具列表永远等于「全部工具 − 已放入格子的工具」，由系统算差集，不做手工维护。由此保证不会出现「工具既不在格子也不在 ⋯」或「两处重复」。`⋯` 内的动作区（撤销 / 重做 / 适应 / 100%）常驻，不参与重算；用户手调过的 `⋯` 顺序单独记住。

**三类下拉**：

| 格 | 单击 | 长按 | 面板 |
|---|---|---|---|
| 菜单 | 展开应用菜单 | 同单击 | 三列 520×320：文件 / 画布 / 系统，共 15 项 |
| 画布 | 展开画布列表 | 直接新建画布 | 约 260×240：名称 / 元素数 / 时间 / 勾选 + `+ 新建画布` |
| 素材 | 展开素材分组 | 直接开上次用过的分组 | 约 320×380，**一个面板两态**：组列表 → 该组缩略图网格（带返回/搜索/分页） |

- 素材面板点缩略图即插入视口中心并选中，面板不关，方便连插。
- 菜单里的「背景」直接给 4 个色块横排，点即生效，不再开二级；「清空画布」二次确认。
- 上一轮定过的「画布列表放在顶部条」保留为第二条入口：顶部的画布名同样可点开。
- 不做固定底部条：动作全部并进 `⋯`。

**互斥**：菜单 / 画布 / 素材 / ⋯ / 笔尖气泡，同一时刻只允许开一个；开新的自动关旧的。任何展开态下暂停画布输入，点画布空白即关闭且不落笔。

## 6. 渲染层与 Bridge

### 6.1 加载

- Electron 用 `loadFile` 加载 `Resources/Sketch/index.html`，Vite 的 `base` 必须是 `./`（`file://` 下绝对路径会 404）。
- 窗口 `show: false` + `ready-to-show` 才显示，避免白屏过程。
- 不起本地 HTTP 服务，减少一层可攻击面；CSP 保持 `default-src 'self' data: blob:`，不请求外部 CDN。
- `Resources/Sketch` 是构建产物，只由 `npm run build` 生成，不手改。

### 6.2 进程间接口

```text
主进程 → 渲染进程
  pen:samples   [[x, y, pressure, phase], ...]   笔采样，phase 1/2/3 = 起/移/抬
  pen:selftest  触发自测笔迹
  menu:settings 菜单栏点「设置…」

渲染进程 → 主进程
  scene:change  场景有改动（用于脏标记与自动保存）
  file:save / file:open / file:export
  board:*       多画布的增删改查
  app:open-settings
```

渲染进程内部的 chrome ↔ 画布通道（不经 IPC）：

```text
setTool(name) / getTool() / hasSelection()
undo() / redo()
zoomToFit() / setZoom(v) / getZoom()
setBackground(plain|dark|dots|grid) / clearCanvas() / elementCount()
setStyle(patch) / getContext()
insertLibraryItem(id)
openRadialMenu(x, y) / openStyleBubble(anchor)
setTabletChrome(on)
```

### 6.3 笔采样注入

Electron 里有两个选择，首版先用 A，A 通了再评估 B。

**A · 合成 PointerEvent（不改源码即可用）**

preload 拿到 IPC 采样后，直接在 canvas 上派发 `pointerdown/move/up`，`pointerType: "pen"`、`pointerId` 固定。

一个必须避开的坑：Excalidraw 把 `event.pressure === 0.5` 当作"设备没有压感、改用速度模拟"的标记（`App.tsx` 里 `simulatePressure`），一旦起笔那帧正好是 0.5，整条线的压感会被丢弃。所以注入前要把压力值钳开 0.5（`0.5 → 0.5001`）。

**B · 直连绘制链路（fork 后做）**

在 `App.tsx` 里加 `pushPenSample(sample)`，把采样直接喂进 `handleCanvasPointerDown` 之后的处理函数，跳过 DOM 事件层。收益是少一跳、压感与倾斜字段完全可控、笔的三态由我们自己判断。这是 fork 的主要理由之一。

**验证顺序**：先做 A 的 PoC，确认能画出带压感的线；再做 B，对比两条线在同一笔输入下的形态与延迟。B 不达标就退回 A，功能不受阻。

**兜底**：如果两条路都拿不到真实压感，用 `perfect-freehand` 包一层自定义 brush 生成 `freedraw` 元素，压感只影响线宽。

## 11. 已知限制

- Excalidraw 钉死在 0.18.1，不再跟随上游；安全修复靠手动 cherry-pick，存在滞后风险。
- Electron 包体积 150–200 MB，冷启动 1–2 s，这是换架构的既定代价。
- 合成 PointerEvent 时，`pressure === 0.5` 会被 Excalidraw 判定为"无压感设备"而丢弃真实压力，注入前必须钳开。
- 文字内联编辑器仍是网页输入框，只能靠样式对齐，无法原生化。
- 只读 HID 可能受输入监控权限影响；权限被拒时只能回退鼠标。
- 8 个板载键需要 vendor 模式初始化；初始化失败时按键不可用。
- 画布锁定在窗口失焦时可能把笔点送到背后 App；必须自动解除。
- 官方驱动与自研输入同时运行时可能双事件；首版只保证单源。
- 首版只支持 Deco 640；其他型号需要新增 `TabletProfile`。
